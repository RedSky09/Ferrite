# M4: Asset loading, spritesheets, animation, bitmap font

**Result:** a new `ferrite-assets` crate loads PNGs, slices them into
spritesheets, drives keyframe animation, and bakes a built-in bitmap font.
`Graphics` gained `upload_image`, `draw_frame`, and `draw_text`, and the
renderer now draws one call per texture instead of one for the whole frame. The
demo (`examples/m4_assets.rs`) loads a PNG, animates it, moves it with the
arrow keys, and draws text over it.

## Design decisions

**Assets are a separate crate, with no GPU dependency.** `ferrite-assets`
decodes, slices, animates, and bakes glyphs, but it never touches wgpu. It
hands the renderer plain RGBA pixels. That split is why its 21 tests run
without a GPU, and why the animation and font logic can be tested as pure
functions.

**`Image` is the one currency.** Everything produces or consumes `Image`:
`Image::load_png`, `Spritesheet`, and `Font::builtin`. It is tightly packed
RGBA8 with a length check on construction, which is exactly what
`Texture::from_rgba8` wants, so upload is a pass-through.

**`image` with only the `png` feature.** The `image` crate pulls in every
format by default. Since M4 only needs PNG, default features are off and only
`png` is enabled, which keeps the dependency tree and build time down.

**Atlases replace the single built-in texture.** Before M4 the renderer had one
hard-coded checkerboard. Now `Graphics::upload_texture` mints an `Atlas` handle
and the renderer keeps a list of bind groups. Handle 0 is reserved for a 1x1
white texture, so an untextured sprite is just a full-uv quad over white and
tinting it gives the solid rectangles the engine always had.

**Sprites carry a uv sub-rect.** A `Sprite` now has `atlas` and `uv` fields.
Drawing a spritesheet frame is `Rect::uv(image_w, image_h)` copied into the
vertex uvs, so a frame is just a quad sampling part of the atlas. This is what
makes one texture able to hold many sprites and the whole font.

**Draw calls are grouped per atlas.** With several textures in play a single
draw call is no longer possible, so `group_sprites_by_atlas` sorts sprites by
atlas and the renderer issues one indexed draw per contiguous run. Sprites keep
painter's order within an atlas, and groups follow first use, so layering is
preserved except across different textures. The demo is exactly two draw calls:
the spritesheet and the font atlas.

**The font is baked, not loaded.** Rather than shipping a PNG and a parser, the
font is a table of 5x7 column-bitmap glyphs for printable ASCII, baked into an
`Image` at startup. It costs no file to find and goes through the same texture
path as everything else. The atlas is 570x7 (95 glyphs of 5px plus 1px
spacing), which is what shows up in the runtime log.

**Uploads are deferred.** `upload_texture` does not touch the GPU; it queues the
pixels and returns the handle immediately. The renderer drains the queue at the
start of `render`, before building vertices, so a texture can be used in the
same frame it was created. That is why the demo can upload from `update`.

## Observations

The headless test earned its keep. Sorting and batching sprites is the kind of
code that can look right and silently drop a sprite or draw the wrong texture,
so I pulled the grouping into a pure function and tested it directly: single
atlas, interleaved atlases, painter's-order preservation, and the
contiguous-start invariant. Then I added an offscreen test that renders to a
texture and reads the pixels back, so placement, tinting, and uv selection are
verified on real hardware, not argued about.

The first offscreen attempt hit three wgpu 30 API changes at once
(`SurfaceConfiguration` gained `color_space`, `PollType::Wait` became a struct
variant, and `get_mapped_range` returns a `Result`). Reading the vendor source
in the cargo registry was faster than guessing.

## Technical notes

- Versions: `image` 0.25.10 (png only), wgpu 30.0.1.
- `Animation` stores no clock; the caller keeps elapsed time and calls
  `sample(ms)`. Looping wraps, one-shot holds the last frame.
- `Rect::uv` maps pixels to uv with v growing downward, matching the vertex
  convention from M2d/M2c.
- The font atlas covers 0x20..=0x7E; out-of-range or missing glyphs are skipped
  but still advance the cursor, so text does not collapse.
- The example asset (`examples/assets/spinner.png`, 64x16) is generated by
  `cargo run -p ferrite-assets --example gen_assets` and committed.
- Tests: 21 in `ferrite-assets`, 13 in `ferrite-render` (plus 4 headless GPU
  tests in `tests/headless.rs`).
